Sửa Bài & Thực Hành Phân Tích Trường Hợp Bằng Flowchart

Mục tiêu đầu ra: Thành thạo kỹ thuật phân tích trường hợp, biết dùng Flowchart để phát hiện lỗi logic trong code và sửa các dạng lỗi phổ biến khi kết hợp if + loop.

1. Lý thuyết cốt lõi (20 Phút)

1.1 Phân tích trường hợp (Case Analysis)

Phân tích trường hợp là kỹ năng liệt kê tất cả trường hợp đầu vào có thể xảy ra trước khi code, bao gồm cả trường hợp bình thường và trường hợp biên (edge cases).

📋 Kỹ thuật "Bẻ gãy bài toán lớn thành nhỏ":
  1. Xác định đầu vào cụ thể: Giới hạn, kiểu dữ liệu, miền giá trị hợp lệ.
  2. Liệt kê edge cases: Số 0, số âm, giá trị tối đa, chuỗi rỗng…
  3. Vẽ Flowchart từng trường hợp: Mỗi nhánh rẽ là một trường hợp.
  4. Code và test từng trường hợp: Viết test case trước khi code chính.

1.2 Chữa lỗi thông qua Flowchart

Khi code chạy sai, hãy vẽ Flowchart thực tế (mô tả những gì code đang thực sự làm) và so sánh với Flowchart kỳ vọng (mô tả những gì ta muốn). Điểm khác biệt chính là chỗ có lỗi.

1.3 Các dạng lỗi thường gặp khi kết hợp if + loop

⚠️ 3 dạng lỗi phổ biến:
  • Logic điều kiện ngược: Dùng < thay vì <=, hoặc == thay vì !=.
  • Thoát vòng lặp sai lúc: Thiếu break hoặc điều kiện while sai.
  • Khởi tạo biến sai vị trí: Đặt khởi tạo trong vòng lặp thay vì ngoài (reset mỗi lần).

1.4 Bài thực hành chữa lỗi

Phân tích 3 đoạn code lỗi sau, xác định lỗi và sửa lại:

Lỗi 1: Kiểm tra số nguyên tố

Phân tích

Đoạn code sau có 2 lỗi. Hãy tìm và giải thích:

loi_nguyen_to.cpp (CÓ LỖI) 
// LOI 1: Thieu break sau khi tim thay uoc → ket qua van dung nhung cham
// LOI 2: Dieu kien i < n nen la i*i <= n → toi uu thuat toan
bool isPrime = true;
for (int i = 2; i < n; i++) {   // LOI: nen i*i <= n
    if (n % i == 0) isPrime = false; // LOI: thieu break;
}

Giải thích lỗi:

  • Lỗi 1: Thiếu break — khi tìm thấy ước số, code vẫn tiếp tục kiểm tra các số tiếp theo không cần thiết. Kết quả đúng nhưng hiệu suất kém.
  • Lỗi 2: Điều kiện i < n thay vì i * i <= n — Toán học chứng minh: nếu n có ước, thì ít nhất một ước phải ≤ √n. Dùng i*i <= n giảm vòng lặp từ O(n) xuống O(√n).
nguyen_to_dung.cpp (ĐÃ SỬA) 
bool isPrime = true;
if (n < 2) isPrime = false;

for (int i = 2; i * i <= n; i++) {   // SUA: i*i <= n
    if (n % i == 0) {
        isPrime = false;
        break;                           // THEM: break de thoat som
    }
}

Lỗi 2: Vòng lặp điều kiện sai

Phân tích

Tại sao kết quả sum bị thiếu? Sửa lại:

loi_while.cpp (CÓ LỖI) 
int sum = 0;
int i = 1;
while (i < 10) {   // LOI: nen i <= 10
    sum += i;
    i++;
}
// Ket qua: sum = 1+2+...+9 = 45 (thieu so 10!)

Giải thích: Điều kiện i < 10 thoát vòng lặp khi i = 10, tức là số 10 không được cộng vào. Phải dùng i <= 10.

while_dung.cpp (ĐÃ SỬA) 
int sum = 0;
int i = 1;
while (i <= 10) {   // SUA: <= thay vi <
    sum += i;
    i++;
}
// Ket qua dung: sum = 1+2+...+10 = 55

Lỗi 3: Logic vòng lặp do-while

Hard

Đoạn code đếm số âm trong dãy nhập đến khi gặp 0. Lỗi nằm ở đâu?

loi_do_while.cpp (CÓ LỖI) 
// Muc tieu: Dem so am trong day nhap den khi gap 0
int x, count = 0;
do {
    std::cin >> x;
    if (x < 0) count++;
} while (x != 0);
// Vay de bai nay co loi khong? Neu co, loi o dau?

Phân tích: Đoạn code này thực ra không có lỗi logic nghiêm trọng — do-while đọc x trước, kiểm tra x < 0 rồi mới kiểm tra điều kiện thoát x != 0. Số 0 không được đếm là âm (đúng). Tuy nhiên:

  • Comment trong đề có ghi "LOI: nen kiem tra truoc khi cap nhat" — đây là lỗi hiểu nhầm. Thực ra cấu trúc do-while đọc x rồi mới dùng x là đúng.
  • Lỗi thực tế có thể xảy ra: Nếu đề yêu cầu "không đếm số 0" → code hiện tại đúng. Nhưng nếu yêu cầu "đếm cả số 0 là không âm" → vẫn đúng vì x < 0 không bao gồm 0.
💡 Bài học: Trước khi sửa code, hãy vẽ Flowchart mô tả những gì code đang làm và so sánh với yêu cầu thực tế. Đừng sửa code chỉ vì "trông có vẻ sai".

2. Bài tập trên lớp — Debug Session (40 Phút)

Thực hành: Vẽ Flowchart từ code lỗi

Trên lớp

Đề bài: Giảng viên phát code lỗi. Học viên thực hiện theo 3 bước:

  1. Vẽ Flowchart thực tế — mô tả chính xác những gì đoạn code đang làm (không phải ý định của tác giả).
  2. Vẽ Flowchart kỳ vọng — mô tả những gì chương trình nên làm theo yêu cầu đề bài.
  3. Chỉ ra điểm khác biệt giữa 2 Flowchart → đó là vị trí lỗi → sửa code.
🎯 Mục tiêu: Thành thạo kỹ thuật đọc code như một máy tính — không đoán ý định, chỉ theo đúng từng dòng lệnh.

3. Bài tập về nhà (Tự luyện tập)

Học viên hoàn thành các bài tập sau về phân tích và sửa lỗi:

Bài 1 [Easy]: Tìm và sửa 3 lỗi

Easy (40%)

Đoạn code sau có 3 lỗi. Hãy tìm, giải thích lý do sai và sửa lại từng lỗi:

ba_loi.cpp (CÓ 3 LỖI) 
#include <iostream>

int main() {
    int n;
    std::cout << "Nhap n: ";
    std::cin >> n;

    int tong = 1;          // LOI 1: ?
    for (int i = 0; i < n; i++) {  // LOI 2: ?
        tong += i;
    }
    std::cout >> tong;      // LOI 3: ?
    return 0;
}
  • Lỗi 1: tong = 1 → phải là tong = 0. Giải thích: Giá trị khởi tạo ban đầu làm lệch kết quả cộng dồn.
  • Lỗi 2: i = 0; i < n → phải là i = 1; i <= n. Giải thích: Vòng lặp từ 0 đến n-1 thay vì 1 đến n.
  • Lỗi 3: std::cout >> tong → phải là std::cout << tong. Giải thích: >> là toán tử nhập (cin), không phải xuất (cout).
ba_loi_dung.cpp (ĐÃ SỬA) 
#include <iostream>

int main() {
    int n;
    std::cout << "Nhap n: ";
    std::cin >> n;

    int tong = 0;              // SUA 1: khoi tao = 0
    for (int i = 1; i <= n; i++) {  // SUA 2: i=1, i<=n
        tong += i;
    }
    std::cout << tong;        // SUA 3: << thay vi >>
    return 0;
}

Bài 2 [Medium]: Chú thích nâng cấp Flowchart Game Đoán Số

Medium (40%)

Vẽ Flowchart hoàn chỉnh cho game đoán số phiên bản 1 lượt (đã làm ở Giai đoạn 01). Sau đó, dùng màu đỏ / mũi tên chú thích vào Flowchart những điểm cần nâng cấp để biến thành phiên bản nhiều lượt (cần thêm vòng lặp ở đâu? thêm điều kiện gì?).

Gợi ý nâng cấp cần chú thích:
  • Thêm vòng lặp do-while bọc quanh phần đoán
  • Thêm điều kiện thoát: guess == secret
  • Thêm đếm số lần đoán: attempts++

Flowchart phiên bản nhiều lượt (các bước đánh dấu [MỚI] là phần cần thêm so với bản 1 lượt):

flowchart_doan_so.txt 
( START )
    |
[ secret = rand() % 100 + 1 ]
[ attempts = 0 ]                       <-- [MOI] khoi tao bien dem
    |
    v
+--> [ Nhap guess ]                    <-- [MOI] diem quay lai cua vong do-while
|       |
|   [ attempts++ ]                     <-- [MOI] dem so lan doan
|       |
|   < guess == secret ? > --Dung--> [ In "Chinh xac sau attempts lan" ] --> ( END )
|       | Sai
|   < guess < secret ? > --Dung--> [ In "Lon hon!" ] --+
|       | Sai                                         |
|   [ In "Nho hon!" ] --------------------------------+
|                                                     |
+-----------------------------------------------------+  <-- [MOI] mui ten quay lai
💡 Điểm mấu chốt: Chỉ có một điều kiện thoát vòng lặp là guess == secret. Mọi nhánh gợi ý "Lớn hơn / Nhỏ hơn" đều phải có mũi tên quay ngược về bước nhập — đó chính là vòng lặp do-while.

Bài 3 [Hard]: FizzBuzz nâng cao

Hard (20%)

Phân tích bài toán FizzBuzz nâng cao: In từ 1 đến n; chia hết 3 → in "Fizz"; chia hết 5 → in "Buzz"; chia hết cả 3 và 5 → in "FizzBuzz"; còn lại → in số. Vẽ Flowchart đầy đủ (chú ý thứ tự kiểm tra!) và viết code tối ưu dùng if-else if-else.

⚠️ Bẫy thứ tự kiểm tra: Phải kiểm tra % 15 == 0 (chia hết cả 3 và 5) trước khi kiểm tra riêng lẻ % 3 hay % 5. Nếu không, trường hợp FizzBuzz sẽ bị bắt bởi nhánh sai.
fizzbuzz.cpp 
#include <iostream>

int main() {
    int n;
    std::cout << "Nhap n: ";
    std::cin >> n;

    for (int i = 1; i <= n; i++) {
        if (i % 15 == 0) {         // Kiem tra chia het 15 TRUOC
            std::cout << "FizzBuzz";
        } else if (i % 3 == 0) {
            std::cout << "Fizz";
        } else if (i % 5 == 0) {
            std::cout << "Buzz";
        } else {
            std::cout << i;
        }
        std::cout << " ";
    }
    std::cout << std::endl;
    return 0;
}
💡 Giải thích thứ tự: i % 15 bắt được cả "chia hết 3" và "chia hết 5". Nếu đảo thứ tự, số 15 sẽ bị in là "Fizz" thay vì "FizzBuzz".
